## 4. Android ABI matrix (verified, not claimed)

Release AAR `tor/build/outputs/aar/tor.aar` (built `-PreleaseBuild=true`) and published `tor-android-0.2.0.aar`:

| ABI | `.so` | Size |
|---|---|---|
| arm64-v8a | `jni/arm64-v8a/libarti_kmp_ffi.so` | 7,923,168 |
| armeabi-v7a | `jni/armeabi-v7a/libarti_kmp_ffi.so` | 5,076,332 |
| x86_64 | `jni/x86_64/libarti_kmp_ffi.so` | 8,981,448 |

No `x86`/i686. **Compatibility change**: 32-bit x86 emulators/devices are no longer supported — Ubique 1.2.1 exposes no x86 Android release target, and the plugin was deliberately not forked/patched. 32-bit ARM (`armeabi-v7a`) is retained. README documents this.
Note: a stale `tor-release.aar` (Gobley-era, 4 ABIs, Jun 25) was found in the local `build/` dir (gitignored); CI pins the explicit `tor.aar` path so it cannot mask a regression.

## 5. Apple SQLite symbol audit (release blocker — PASS)

- Hook: `tasks.withType<CargoBuildTask>` + `doLast`, Apple detection via `rustTarget.rustTriple.contains("apple")`, processes `staticLibraryFile`, hard-fails the build if `hide-sqlite3-symbols.sh` exits non-zero. Script itself untouched.
- `llvm-nm` check on `tor/build/uniffi/build/rust/aarch64-apple-ios/release/libarti_kmp_ffi.a` and `…/aarch64-apple-ios-sim/release/…`: **no global `_sqlite3*` symbols** in either.
- Control: pristine cargo outputs under `rust/arti-kmp-ffi/target/<triple>/release/` **do** contain global `_sqlite3*` → proves the hook ran and the clean result is not vacuous.
- Both `compileKotlinIosArm64` and `compileKotlinIosSimulatorArm64` (release) succeed through cinterop with the processed archives; no duplicate-symbol errors.
